# Phase 12.5 Spec — 切换到 @earendil-works/pi-ai

> 状态：Design 已对齐（2026-05-13），待用户审阅本 spec → 进入 writing-plans。
> 关联 roadmap：[`docs/requirements/roadmap.md` Phase 12](../../requirements/roadmap.md)
> 前置：Phase 12 ✅ 代码完成（22 commit，未部署）
> 后续候选：Phase 12.6（OAuth providers）/ Phase 13（pi-agent-core 上移 useAIChat）

## 1. 目标

把当前 Phase 12 自研 LLM 抽象层的 **SDK 调用 + protocol translation** 部分换成 `@earendil-works/pi-ai`（pin 0.74.0，OpenClaw 同款）。骨架（canonical 类型、SSE wire、route shell、frontend、Settings UI、DB schema）**一行不动**。

**为什么切**：

- pi-ai 是 OpenClaw（371K star，OpenAI 官方赞助）的 agent 核心，validation 充分
- 提供 25+ provider（我们 7 个） vs 我们自研的 3 个 native adapter，立即拿到 Mistral / Groq / xAI / OpenRouter / Cerebras 等
- 自带 cost tracking（pi-ai 每次响应返 `usage.cost`，单位 USD），不需要我们建 token pricing 表
- 自带 partial JSON tool args streaming（我们也有，零损失）
- 自带 cross-provider context handoff backend hook（pi-ai 的 `Context` 设计天然支持，本 phase 不接 UI）
- SDK 协议跟进负担转给 pi-ai 社区（Anthropic / OpenAI / Google SDK 升级时不用我们改 adapter）
- 我们删 ~700 LOC + ~200 个 SDK 协议测试，加 ~1 个 adapter 文件 + ~30 个测试

## 2. 不做什么（范围围栏）

- ❌ **不接 OAuth providers**（Codex / Copilot / Vertex / Bedrock）— pi-ai 支持但需 redirect URI + token refresh + UI flow，工作量 ≥ 1 周；**延 Phase 12.6 候选**
- ❌ **不切换 image generation**：pi-ai 的 image gen 走 OpenRouter 中转（加价 + 加依赖 + 同模型），违反 memory `image-gen-provider-scope`。`generate_slide_image` 继续走 `openai-image.ts` 独立路径。pi-ai 的 API 设计技巧可作 follow-up TODO 学但不切代码
- ❌ **不引入 pi-agent-core**：它是 agent runtime 层（替代 useAIChat 的 tool loop + state management），引入会让 Phase 12.5 范围爆炸（3-4 天 → 7-9 天）+ 第二次重写 Task I 刚落地的代码 + 浏览器兼容性未验证。延 **Phase 13 候选**，dogfood 后基于实测痛点（parallel tool / steering / sessionId caching）再定
- ❌ **不接 cross-provider handoff UI**：pi-ai 内置「同 context 喂给不同 model」backend 能力本 phase 自动有；frontend「换 provider 继续」按钮延后
- ❌ **不引入 dynamic provider 全列表**：Settings UI 只暴露白名单 12 个 provider（避免 25+ 全展示导致 UI 杂乱 + 我们没测过的 provider）
- ❌ **不改 canonical event 名对齐 pi-ai**：会冲击 frontend useAIChat 状态机 + SSE wire encoder/decoder + 测试 fixtures，无收益

## 5. pi-ai event 映射到 canonical event

pi-ai 发的 11 类事件 → 我们 canonical 的 8 类事件映射表：

| pi-ai event | canonical event | 说明 |
|---|---|---|
| `start` | （drop） | pi-ai 的 stream 启动信号，canonical 不需要 |
| `text_start` | （drop） | text block 开始信号，canonical 用 delta 自包含 |
| `text_delta` | `text.delta { text }` | 1:1 |
| `text_end` | （drop） | text block 结束信号 |
| `thinking_start` | （drop） | 同上 |
| `thinking_delta` | `thinking.delta { text }` | 1:1 |
| `thinking_end` | （drop） | |
| `toolcall_start` | `tool_call.start { id, name }` | 1:1（pi-ai 用 `contentIndex`，canonical 用 id；adapter 自维护 id↔index 映射） |
| `toolcall_delta` | `tool_call.delta { id, argsChunk }` | 同上 |
| `toolcall_end` | `tool_call.end { id }` | 同上 |
| `done` | **2 个 event**：先 `cache.hit { cachedTokens, costTokens }`（如 `usage.cachedRead > 0`），再 `finish { reason, usage: { input, output, cached?, cost? } }` | pi-ai 用一个 done event 带 usage，canonical 拆 cache.hit + finish |
| `error` | `error { code, message }` | code 按 pi-ai error 类型映射到 6 个 LLMErrorCode（rate_limit / auth / network / invalid_request / context_too_long / unknown） |

**关键设计点**：
- 所有「start / end 包络」事件 silent drop——canonical 用 delta 自包含信息（id + name 在 start，args 在 delta，end 不带额外信息）
- pi-ai 的 `contentIndex`（多个 tool call 并发时用 index 区分）在 adapter 里维护 `Map<index, { id, name }>`，emit canonical event 时输出 string id
- pi-ai 的 `done.usage.cost` 是 USD 浮点数，**直接透传**到 canonical `finish.usage.cost`，frontend 渲染时按汇率换算（汇率写死或从环境变量读，本 phase 写死 ~7.2 RMB/USD）
- canonical `cache.hit` 仅在 `usage.cachedRead > 0` 时 emit；pi-ai 的 cache 字段命名待 SDK 确认（`cachedRead` / `cachedWrite` / `cachedInput` 之一）—— Task 实施时打印实际字段名再固化映射

## 6. cost tracking 数据流

```
LLM 上游响应 → pi-ai stream() done event
  ↓ usage.cost = { total: 0.0012, input: 0.0003, output: 0.0009 } (USD)
  ↓ usage.cachedRead = 12450 tokens (anthropic prompt caching 命中)
pi-ai-adapter
  ↓ 拆 done event:
  ↓   1. emit canonical 'cache.hit' { cachedTokens: 12450, costTokens: 89 }
  ↓   2. emit canonical 'finish' { reason: 'stop', usage: { input: 89, output: 234, cached: 12450, cost: { total: 0.0012, input: 0.0003, output: 0.0009 } } }
routes/llm.ts eventsToSSEStream
  ↓ SSE wire 透传
frontend useAIChat decodeSSEStream
  ↓ on event.type === 'finish':
  ↓   lastUsage.value = evt.usage
  ↓   if (evt.usage.cost) lastCost.value = evt.usage.cost
UsageStatsHint.vue 渲染
  「本轮 234 output tokens / 缓存命中 12450 tokens」
  「¥0.0086 = $0.0012 × 7.2」
  「相比无缓存节省 ~93%（cost.input / (cost.input × (1 + cached/active)) 比例）」
```

**前端展示规则**：
- 汇率：写死 `USD_TO_RMB = 7.2`，TODO 注释「未来配置化」
- 显示：`¥` 取 4 位小数（最小单位 0.0001 元约等于 0.0014 美分，足够分辨小成本）
- cost.total = 0 时不显示 cost 那一行（pi-ai 对某些 free-tier provider 返 0）
- cachedRead > 0 时额外显示「缓存节省 ¥X.XXXX」（用 cost.input ratio 估算）

## 7. dynamic model dropdown 数据流

```
SettingsModal.vue 打开
  ↓ 用户展开 anthropic card
  ↓ 调用 GET /api/llm/models?provider=anthropic
routes/llm-settings.ts (new endpoint)
  ↓ pi-ai.getModels('anthropic')
  ↓ 返回 Model[] {id, name, capabilities, ...}
frontend
  ↓ 渲染 <select> options
  ↓ 用户选 model
  ↓ 保存触发 PUT /api/auth/llm-settings (现有 zod-validated 路径)
```

**实现细节**：
- `getModels()` 在 adapter 模块 level cache（每个 provider 一份，进程 lifetime 内不刷新）—— 避免每次 settings open 都查
- 没配 apiKey 的 provider card 不调 getModels（节省）
- pi-ai `getModels()` 报错时降级到 `PROVIDER_CATALOG[id].defaultModel` 作单选项
- model select 允许「自由输入」（高级用户填 SDK 没列出但 provider 实际支持的 model id）——antdv `<a-select>` 设 `:allow-clear` + `mode="combobox"` 即可

**新增 5 个 provider 价值**：
- Mistral：欧洲合规场景 / 开源生态
- Groq：超低 latency（10x 普通 inference），适合 chat UX
- xAI：实时数据访问（X/Twitter 数据），潜在 RAG 增强
- OpenRouter：一个 key 调所有模型 + 价格 transparent，适合预算敏感用户
- Cerebras：超低 latency（号称 1800 tokens/s），适合即时反馈场景

## 9. 错误处理

`pi-ai-adapter` 的 `translatePiAiError(e, providerId): LLMError`：

pi-ai 错误类（参考 pi-ai 源码 + dogfood 期间补全）：
- `AuthenticationError` (401/403) → `'auth' / retryable=false`
- `RateLimitError` (429) → `'rate_limit' / retryable=true`
- `BadRequestError` (400 含 'context window' / 'too long' / token 关键字) → `'context_too_long' / retryable=false`
- `BadRequestError` (其他 400) → `'invalid_request' / retryable=false`
- `ServerError` (5xx) / `NetworkError` / `TimeoutError` → `'network' / retryable=true`
- `AbortError` → `'unknown' / retryable=false`（client cancel，不是 bug）
- 默认 → `'unknown' / retryable=false`

`cause: e` 透传保留 pi-ai 原 error 给 logServerEvent。

## 11. 部署 / migration

**无 DB migration**（DB shape 跟 Phase 12 落地一致），但有 **运行时配置变化**：

- 老用户配过的 `users.llm_settings.providers.{openai/anthropic/gemini/zhipu/deepseek/moonshot/qwen}` 全继续工作
- 新加的 5 个 provider（mistral/groq/xai/openrouter/cerebras）默认 `providers` 字典里没条目，UI 卡片显示「未配置」状态
- 老用户 `model` 字段写的字符串（如 `claude-sonnet-4-5`）如果不在 pi-ai `getModels('anthropic')` 列表里，UI dropdown 显示「自定义：claude-sonnet-4-5」并允许保留——`<a-select>` combobox 模式

**SDK 依赖卸载**：

```
pnpm -F @big-ppt/agent add @earendil-works/pi-ai@0.74.0
pnpm -F @big-ppt/agent remove openai @anthropic-ai/sdk @google/genai
```

pin minor 版本（OpenClaw 用 0.74.0），不跟 npm `latest`（pi-ai 可能频繁发版）。

**注意**：移除 3 个 native SDK 前**先验证 pi-ai 是否 transitively depend on them**——如果 pi-ai 内部用了 `openai` / `@anthropic-ai/sdk` 作 peer dep，pnpm dedupe 会自动保留；如果 pi-ai 完全自带 HTTP client，则 3 个顶层依赖可彻底移除。Task 实施时先 `pnpm install` 看 lockfile 变化决定。

**部署流程**：与 Phase 12 一致（`pnpm deploy:backend` + ssh migration + `pnpm deploy:creator` + healthz），无新增步骤。
